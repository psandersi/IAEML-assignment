## Постановка эксперимента

Агент обучается непрерывному управлению в среде из Assignment 1. Наблюдение состоит
из 39 чисел, действие — из ускорения и целевого угла колеса. Состояния, награда,
столкновения и ограничение времени описаны в [отчёте о среде](assignment1.md).
Код PPO написан в JAX/Optax в `src/algorithms/ppo.py`; цикл эксперимента — в `src/train.py`.
Готовая сторонняя реализация PPO не копируется.

Обучение проводится на карте 0. Карты 1 и 2 используются только для оценки переноса.
Карты заранее заданы; поле статической навигации доступно и при оценке. Поэтому
это обучение локальному управлению с навигационными подсказками, а не построение
глобального маршрута исключительно нейросетью.

Политика получает только наблюдение: ни контроль baseline, ни экспертное действие
не добавляются к выходу сети. Чекпойнт `untrained.npz` фиксирует начальную политику
того же запуска до первого обновления. Это позволяет сравнить эффект обучения,
а не только отличия разных инициализаций.

## Алгоритм и модель

PPO — on-policy actor–critic алгоритм. Actor выбирает действие, critic оценивает
дисконтированную сумму будущих наград. Сеть actor и сеть critic отдельные: по два
скрытых слоя ширины 64 с `tanh`. Actor возвращает два средних нормального распределения;
два логарифма стандартного отклонения обучаются отдельно от наблюдений. Изначально
они равны −0.5. Выход critic — скаляр `V(s)`.

При обучении выбирается `z = μ(s) + σ ε`, затем `a=tanh(z)`. При оценке применяется
детерминированное `a=tanh(μ(s))`. В rollout сохраняется `z`, а не обратное преобразование
ограниченного действия. Отношение вероятностей рассчитывается для одинакового `z`:
якобиан `tanh` сокращается между старой и новой политикой. Для регуляризации
используется энтропия исходного Normal, а не точная энтропия распределения после `tanh`.
Это приближение; оно не учитывает насыщение действия у границы.

Целевая функция actor:

\[
L_{clip}=E[\min(r_t A_t,\operatorname{clip}(r_t,0.8,1.2)A_t)],
\qquad r_t=\pi_\theta(z_t|s_t)/\pi_{old}(z_t|s_t).
\]

В коде минимизируется `-L_clip + 0.5 L_value - 0.005 H`. Для critic используется
максимум квадратов обычной и ограниченной ошибки значения с множителем 1/2.
Advantage стандартизируется по всему rollout. Ограничение PPO снижает величину
обновлений, но само по себе не гарантирует улучшение политики на каждом шаге.

Для GAE используются:

\[
\delta_t=r_t+\gamma(1-terminated_t)V(s_{t+1})-V(s_t),
\quad A_t=\delta_t+\gamma\lambda(1-done_t)A_{t+1}.
\]

При столкновении и успехе bootstrap равен нулю. При лимите времени используется
значение настоящего последнего наблюдения до сброса. Рекурсия advantage обрывается
при любом завершении, чтобы не переносить награды следующего эпизода в предыдущий.

Это конфигурация запущенного конвейера, а не заявление, что все расчёты завершились.

Остановка фонового процесса не должна интерпретироваться как успешное обучение.

Оценка проводится для четырёх политик: случайная, необученный actor, обученный PPO и
явный эвристический контроллер. Для каждой — по 32 эпизода на каждой из трёх карт.
Evaluation seed `20261120` отличается от обучающих seed. Начальные условия для политик
совпадают. Варьируются положение и направление старта; фазы и размещение препятствий
остаются фиксированными. Метрики: доля достижения цели, столкновений и таймаутов,
средняя награда, длина эпизода и остаточное расстояние до цели.

95% интервал Wilson показывается для доли успехов. Разные обучающие seed представлены
отдельно: эпизоды одного обучения не выдаются за независимые повторения обучения.
Карты 1 и 2 не используются для выбора checkpoint. Сохраняется конечная модель;
лучший результат по тестовой карте не отбирается.

## Вычислительные оптимизации

1. `vmap` вычисляет переходы 64 сред совместно, сохраняя данные в JAX.
2. `lax.scan` собирает rollout и выполняет эпохи/минибатчи без Python-цикла по шагам среды.
3. Весь rollout, GAE и обновление PPO объединены в одну JIT-функцию.
4. Навигационное поле рассчитано заранее; дорогостоящий DP не запускается на каждом шаге.
5. Состояния имеют фиксированные формы, вычисления используют float32.
6. Во время обучения нет графического интерфейса и кодирования видео. Видео создаётся
   после обучения. На CPU не запускаются несколько конкурирующих обучений одновременно.
7. В Python копируется только небольшая сводка метрик раз в обновление; модели
   сохраняются каждые десять обновлений и в конце.

`src/benchmark.py` сравнивает последовательные вызовы той же среды в Python и
`vmap+scan`. Обе ветки предварительно компилируются, а время замеряется после
`block_until_ready`. Конечные координаты сравниваются численно.
Фактические значения записываются в `artifacts/benchmark.json`. Сравнение включает
накладные расходы Python у последовательной ветки; это не сравнение разных моделей
физики и не универсальная оценка ускорения JAX. Замер единичный и зависит от устройства.

Скорость обучения в `metrics.jsonl` включает первоначальную компиляцию; её нельзя
напрямую сравнивать с чистой скоростью среды из benchmark. Операционная система,
устройство, версия JAX и команда запуска сохраняются вместе с экспериментом.

проверяется конечность loss, изменение параметров и корректный autoreset.

## Технические сложности и ограничения

При autoreset особенно легко подставить значение нового стартового состояния вместо
финального. В реализации critic вызывается до выбора reset-состояния; отдельный тест
GAE фиксирует эту логику. Насыщение `tanh` не обращается через `arctanh`, поскольку
сохраняется исходное `z`. Логи отражают KL и долю ограниченных отношений вероятностей,
чтобы сильные изменения политики можно было заметить при анализе результатов.

Локальная цель даёт полезную структуру задачи, но не учитывает движущиеся препятствия
в планировании. Агент может выучить неустойчивое торможение или зависнуть у поворота.
Отсутствие памяти ограничивает реакцию на движение препятствий. Набор из трёх карт
не позволяет судить о надёжности в реальном дорожном движении.

## Личная рефлексия 
Самый тонкий момент в PPO - обработка конца эпизода. При столкновении будущая награда обнуляется, а при лимите времени нужно учитывать оценку последнего состояния. Результат обучения стоит оценивать по доле доездов до цели и видео: рост награды сам по себе ещё не означает, что агент хорошо ездит.
