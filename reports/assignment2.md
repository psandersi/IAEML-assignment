# Обучение робо-такси

Daria Galushko, AI-01

Цель эксперимента — проверить, научится ли машина самостоятельно выбирать газ и угол руля. Обучение проходит на карте 0. Карты 1 и 2 используются для проверки переноса. Главная метрика — число доездов из 32 попыток. Для всех контроллеров используются одинаковые стартовые условия.

## Первый эксперимент

После 300 обновлений PPO ни одна из трёх моделей не достигла цели в оценочных эпизодах. На картах 0 и 1 все попытки закончились по времени, на карте 2 — столкновением. На первом видео для seed 42 машина проехала около 9 см за минуту. При этом эталонный контроллер на карте 0 выполнил 32 доезда из 32. Маршрут проходим, но сигнал награды позволял машине получать баллы у старта.

## Повторный эксперимент

Награда теперь учитывает фактическое приближение к ориентиру. Перед обучением с подкреплением сеть делает 4000 обновлений по примерам эталонного контроллера. Примеры состоят из сгенерированных наблюдений и соответствующих команд газа и руля. При движении по карте команды выдаёт сама сеть. Отдельная оценка модели сразу после подражания позволяет увидеть, улучшил ли результат последующий PPO.

Actor и critic — две сети с двумя скрытыми слоями по 64 нейрона. Actor задаёт средние значения двух нормальных распределений. При обучении действие случайно и ограничивается через tanh. При оценке используется среднее, пропущенное через tanh. Critic оценивает будущую награду. PPO сравнивает вероятность выбранного действия до и после обновления и ограничивает её отношение в целевой функции интервалом 0,8–1,2. Для расчёта преимущества используется GAE с γ = 0,99 и λ = 0,95.

Для каждого seed (42, 43, 44) выполняется 100 обновлений по 8192 перехода. Каждая выборка проходит четыре эпохи по восемь минибатчей. Каждые пять обновлений модель проверяется на 16 стартах карты 0 с отдельным ключом 9081. Для итоговой оценки выбирается модель с наибольшим числом доездов. При равенстве выбирается меньшая средняя дистанция до цели. Итоговый ключ 20261120 и карты переноса в выборе модели не участвуют.

## Ход эксперимента

1. Обучили PPO с нуля на карте 0 и сравнили его со случайными действиями, необученной сетью и эталонным контроллером. По видео и координатам проверили, чем заканчивались эпизоды.
2. Изменили награду за движение и добавили предварительное обучение по примерам контроллера. Сохранили веса сразу после подражания, чтобы отдельно измерить его вклад.
3. Для трёх инициализаций сети продолжили обучение с PPO на карте 0. Промежуточные модели сравнивали на отдельных стартах той же карты.
4. Выбранные модели проверили на всех трёх картах. Каждый контроллер получил одни и те же 32 старта на каждой карте. Записали доезды, столкновения, таймауты и видео первого эпизода.

Подражания уже хватило для прохождения первых двух карт. Последующее обучение с PPO сохранило эту долю доездов. Вклад новой награды отдельно не измерялся.

На карте 2 все оценочные попытки PPO закончились столкновением. В первом эпизоде seed 42 машина за 4,2 с доехала до точки (37,94; 11,93) со скоростью 2,83 м/с. Центр движущегося препятствия в этот момент находился в точке (36,00; 11,94). Расстояние между центрами составило 1,94 м при пороге контакта 2 м. Этот эпизод показывает столкновение с пересекающим маршрут препятствием. Для остальных эпизодов сохранён тип исхода, но конкретное препятствие не определялось. Два последовательных наблюдения с лучевых датчиков дали бы сети информацию о том, как меняется свободное расстояние. Для проверки стоило бы сравнить долю доездов и столкновений с текущей моделью. Если саму карту 2 использовать для обучения или подбора параметров, перенос нужно оценивать на другой карте.

## Контрольный эксперимент с наградой

Поможет ли новая награда машине, которая начинает со случайными весами? Для этого сравниваем два запуска PPO с нуля. В первом машина получает исходную награду, во втором — награду за приближение к ориентиру. Для каждой пары совпадают начальные веса, уровень шума действий, ключи генератора случайных чисел и бюджет в 100 обновлений. Чекпойнт выбирается каждые пять обновлений по результатам на карте 0. Оценка проходит на тех же 32 стартах каждой карты.

Разница между этими двумя условиями показывает эффект замены награды при заданном бюджете. Для проверки вклада подражания сравниваем второе условие с уже обученной моделью, которая получила ту же награду после подражания. Результат первоначального запуска на 300 обновлений для такого сравнения не подходит из-за другого бюджета и способа выбора модели.

Команда воспроизведения — `./.venv/Scripts/python.exe scripts/reward_control.py`. После шести запусков скрипт формирует [таблицу доездов и вывод по трём условиям](../artifacts/reward_control/RESULTS.md) из файлов оценки. Для каждого seed приведены отдельные результаты на каждой карте.

## Скорость расчёта

JAX обрабатывает 64 среды параллельно через vmap. Сбор 128 шагов и обновление параметров компилируются с помощью jit и scan. Поле навигации рассчитывается один раз на карту. В исходном замере на CPU 1024 перехода после прогрева заняли 1,04 с в цикле Python и 0,0018 с при пакетном расчёте. Это замер шага среды, включая расходы Python на последовательные вызовы. [Данные замера](../artifacts/benchmark.json)

## Рефлексия

На карте 0 модель с seed 42 набирала в среднем 32,13 балла за поездку. По этой цифре трудно заметить проблему. Все 32 попытки закончились по времени, а в первом записанном эпизоде машина проехала всего около девяти сантиметров за минуту. Сначала можно было подумать, что она застряла у препятствия. Но на записи она почти сразу остановилась у старта. Эталонный контроллер в тех же условиях доехал до цели 32 раза из 32. Значит, физика машины и ширина проезда позволяли пройти маршрут.

Объяснение нашлось в расчёте награды. В первой версии расстояние до цели учитывалось через отрицательный потенциал. На каждом шаге новый потенциал умножался на 0,99, а затем из него вычитался предыдущий. Например, если машина стоит и оба значения равны −5, получается `0,99 × (−5) − (−5) = 0,05`. После штрафа за время при нулевом действии оставалось 0,04 балла, хотя машина никуда не сдвинулась. В первом записанном эпизоде даже необученная сеть простояла на месте и набрала около 40 баллов. При попытке ехать агент рисковал столкнуться и потерять 20 баллов, а до награды за финиш требовалось пройти весь маршрут. Это помогает объяснить, почему в обучении закрепилась остановка.

Во второй версии движение оценивается по тому, насколько за один шаг сократилось расстояние до ближайшего ориентира. Если машина стоит, расстояние остаётся прежним и за шаг снимается 0,015 балла. Именно этот случай теперь проверяет отдельный тест. Для оценки поведения важнее всего число доездов, а затем причины неудач. Столкновение и таймаут одинаково дают ноль доездов, но на первом видео хорошо видно, почему для этих двух случаев нужны разные исправления.

Повторный запуск записывает [таблицу доездов](../artifacts/guided/RESULTS.md), [чекпойнт seed 42](../artifacts/guided/ppo_seed42/best.npz) и [видео на карте 0](../artifacts/guided/ppo_seed42/evaluation/map0_ppo.mp4). После [установки зависимостей](../readme.md) один запуск повторяется так:

```bash
./.venv/Scripts/python.exe src/train.py --guided --seed 42 --updates 100 --save-every 5 --out artifacts/repeat42
./.venv/Scripts/python.exe src/evaluate.py --checkpoint artifacts/repeat42/best.npz
```
